# Контекст для Claude Code

Идёт тестовое задание с **жёстким лимитом в 20 минут**. Главная цель: **рабочий публичный URL как можно раньше**, а не идеальный код.

## Порядок работы (строго)
1. Прочитай задание. Если что-то неоднозначно, выбери самое простое разумное толкование и не задавай вопросов.
2. За первые ~5 минут сделай минимальную рабочую версию → `./deploy.sh` → проверь прод через curl.
3. Сделай коммит и `git push` (ссылку на репо тоже сдают).
4. Затем улучшай маленькими шагами: изменение → `./deploy.sh` → curl-проверка → commit/push.
5. Под конец обнови README.md: что сделано, эндпоинты, примеры curl.

## Стек (не менять)
- Python 3.12 + FastAPI, весь код в `app/main.py` (можно разбить на модули, если вырастет).
- Хранилище: SQLite в `/data/app.db` (хелпер `db()` уже есть). Без внешних БД.
- UI при необходимости: статический `app/static/index.html` с ванильным JS и fetch. Без сборщиков, React и npm.
- Зависимости добавлять в `requirements.txt`.
- CORS уже открыт. `/health` уже есть, не удалять.

## Деплой
- `./deploy.sh` пакует проект, заливает на VPS по ssh и выполняет `docker compose up -d --build`. Затем ждёт `/health`.
- Настройки (ssh-хост, домен) лежат в `deploy.conf`. **Инфраструктуру не трогать**: Dockerfile, docker-compose.yml, Caddyfile, deploy.sh.
- Прод-URL: см. `PUBLIC_URL` в `deploy.conf`.
- Логи: `ssh $SSH_HOST "cd /opt/app && docker compose logs --tail=100 app"`.

## Правила
- Не трать время на тесты, линтеры и рефакторинг. Ручная проверка через curl по проду.
- Не спрашивай подтверждений, просто делай.
- Если деплой упал, сначала смотри логи контейнера.
- Ответы API в JSON, корректные HTTP-коды (400/404 и т.д.), валидация через Pydantic.
